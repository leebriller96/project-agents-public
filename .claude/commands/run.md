# /run — 자동 진행

인자: `$ARGUMENTS`

게이트 판정이 기계화(`tools/gate.py`)됐으므로 단계 전환 때마다 사람이 판단을 대신할 필요가 없다.
이 명령은 **이미 있는 `/stageN`·`/refactor` 절차를 그대로 순서대로 호출**하는 얇은 진행자다. 새 방법론을 만들지 않는다.

## 절차

1. `.claude/skills/pipeline-core/SKILL.md` §1·§4 를 읽는다. `config/project.yaml`·`state.yaml` 을 읽는다.
2. 인자 해석:
   - `--to <stage>`: 여기까지만 진행 (기본: 5).  `--slice <id>|all`: 대상 slice (기본: all).
   - `--max <n>`: 한 번에 실행할 최대 단계 수 (기본: 4). 넘으면 멈추고 다음 명령을 안내한다.
   - `--dry`: 실행하지 않고 **진행 계획만** 출력한다. 처음 쓸 때는 `--dry` 를 먼저 권한다.
3. **다음 실행 가능 단계 계산**: **직접 계산하지 말고 `python tools/gate.py plan --to <N> --max <n>` 을 실행한다.**
   선행 조건(pipeline-core §4)·웨이브 편성(§6)·축 요구(§14)·멈춤 조건을 도구가 한 곳에서 계산한다 —
   명령 본문이 이 계산을 산문으로 재구현하면 어긋난다(첫 실측에서 애드혹 스크립트가 인코딩·문법으로 두 번 깨졌다).
   `--format json` 으로 받아 그대로 쓴다. 출력에는 `steps`(실행할 단계), `deferred`(--max 초과분),
   `waves`, `serial_waves`(slice 1개라 병렬 이득이 없는 웨이브), `axis_requirements`, `stops`, `runnable` 이 들어 있다.
   - `stops` 가 비어 있지 않으면 **아무 단계도 실행하지 않고** 그 내용을 사용자에게 보여준다.
   - 열린 RR 이 임계치(`blocker`/`high` 1건 이상 또는 open 5건 이상)를 넘으면 `plan` 이 `/refactor` 를 먼저 넣어 준다.
   - `--dry` 면 이 출력을 사람이 읽을 형태로 보여주고 **끝낸다**(파일을 쓰지 않는다).
4. **한 단계 실행**: 해당 `/stageN` 명령의 절차를 그대로 수행한다(서브에이전트 호출·웨이브·reviewer 포함).
5. **판정**: 그 단계의 레포트에 `pa-meta` 를 붙이고 `python tools/gate.py check --stage <N> [--slice <id>]` 를 실행한다.
   - 통과(WARN 포함) → `state.yaml` 갱신 후 3번으로 돌아간다.
   - FAIL → **멈춘다.** FAIL 훅·항목과 수정 방법을 사용자에게 보여준다.
6. 끝나면 진행한 단계, 각 단계의 게이트 요약(테스트 수·축), 만든 RR·확인 필요 항목, 누적 비용(`pa-meta.cost` 합)을 표로 보고한다.

## 반드시 멈추는 지점

| 조건 | 이유 |
|---|---|
| `slices.yaml → approved: false` | 1단계 승인은 사람 몫 (pipeline-core §10) |
| `gate.py check` FAIL | 게이트 미통과 |
| `blocker`·`high` 확인 필요 항목이 열린 채 남음 | RR 전환·승인은 판단이 필요하다 |
| reviewer 재작업 2회 후에도 잔여 지적 | `blocked` 보고 |
| RR `rejected` 판단이 필요한 상황 | 사람만 지정 |
| 확인 필요 항목 `accepted`(잔존 승인) 요청 | 사람만 지정 |
| stage0 brief §11·§12, stage2 골격 완료 | 비차단이지만 **요약을 보여주고 한 번 확인받는다** |
| `--max` 도달 | 폭주 방지 |

멈출 때는 항상 (1) 왜 멈췄는지 (2) 사람이 무엇을 결정해야 하는지 (3) 결정 후 이어갈 명령을 함께 보여준다.

## 안전 규칙

- 단계를 **건너뛰지 않는다.** 선행 조건이 미충족이면 그 단계를 실행하지 않고 멈춘다.
- 게이트를 통과시키려고 테스트를 지우거나 범위를 줄이지 않는다. 막히면 멈추는 것이 정상 동작이다.
- 6·7단계는 비용이 크므로 `--to` 에 명시적으로 포함해야 실행한다(기본 5까지).
- 각 단계 종료 시 `state.yaml` 과 target repo 커밋을 남긴다 — 중단돼도 다음 `/run` 이 이어받을 수 있어야 한다.
- 한 `/run` 안에서 같은 단계를 2회 이상 재시도하지 않는다. 실패는 사람에게 보고한다.

## unit 으로 나눈 slice

`gate.py plan` 은 unit 분할 구조 오류가 있으면 멈추고, unit 진행(BE·FE 완료 수)과 분할 후보(units 없는 큰 slice)를 보여 준다. 진행은 `/stage2`·`/stage4` 의 5-U 절차를 따른다 (pipeline-core §20).

## 공통 금지 — 이모지

서브에이전트 프롬프트에 "이모지 금지(pipeline-core §15)" 를 명시하고, 레포트·보고·생성 소스 어디에도 이모지를 쓰지 않는다. 훅이 차단하면 텍스트로 고친다.
